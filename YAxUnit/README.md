## 1. Подключение к базе (единственный ручной шаг)

1. Открыть **Конфигуратор** целевой (тестовой) базы.
2. Меню **Конфигурация → Расширения конфигурации**.
3. **Добавить из файла** → выбрать `Q:\ba\YAxUnit\YAxUnit-25.12.cfe`. Имя расширения — `YAxUnit`.
4. В свойствах расширения **снять** флажки:
   - «Безопасный режим»;
   - «Защита от опасных действий».
   Без этого тесты выполняться не будут.
5. (Опционально) так же добавить `Smoke-25.12.cfe` — расширение `Smoke` с готовыми дымовыми тестами.
6. Запустить **1С:Предприятие** — появится новый раздел **YAxUnit**.

## 2. Первый тест

Тест — общий модуль в расширении. Для пробы можно создать модуль прямо в расширении `YAxUnit` (Общие модули → Добавить, имя например `ОМ_ПервыйТест`):

```bsl
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты.ДобавитьТест("Сложение");
КонецПроцедуры

Процедура Сложение() Экспорт
    Результат = 2 + 2;
    ЮТест.ОжидаетЧто(Результат)
        .Равно(4);
КонецПроцедуры
```

Для постоянных тестов создать отдельное расширение `tests` и писать модули там.

## 3. Запуск

**Интерактивно:** раздел YAxUnit → **«Запуск тестирования»** — тесты отобразятся деревом, запуск и отчёт там же.

**Из конфигуратора:** Сервис → Параметры запуска → в поле параметров указать путь к `Q:\ba\YAxUnit\test-config.json`.

**Из командной строки** (файловый вариант базы):

```
"C:\Program Files\1cv8\8.3.24.1691\bin\1cv8c.exe" ENTERPRISE /F "C:\путь\к\базе" /N Администратор /P пароль /C "RunUnitTests=Q:\ba\YAxUnit\test-config.json"
```

(для серверной базы вместо `/F` — `/S Сервер\База`).

**Запуск из Git Bash:** MSYS конвертирует ключи `/S`, `/C`, `/Out` в пути — обязательно префиксовать запуск:
`MSYS2_ARG_CONV_EXCL="*" MSYS_NO_PATHCONV=1 "C:\Program Files\1cv8\8.3.27.1859\bin\1cv8c.exe" ENTERPRISE /S "10.62.11.48\BitPluse_Dev" /C "RunUnitTests=..."`

**Дымовые тесты (расширение Smoke) по умолчанию ВЫКЛЮЧЕНЫ.** Включаются секцией в конфиге запуска (см. `smoke-config.json`):
```json
"ДымовыеТесты": { "Использовать": true, "ОткрытиеФорм": { "Использовать": true } }
```
Без неё прогон по Smoke завершается за секунды с 0 тестов и кодом 0. Виды: ОткрытиеФорм (открывает формы, безопасный), ЗаписьСправочников, ПроведениеДокументов, ПроверкаПрав (пишут данные — в транзакциях). На больших конфигурациях ОткрытиеФорм — тысячи тестов и десятки минут.

### Отбор объектов дымовых тестов

Дерево настроек: `ДымовыеТесты → ОткрытиеФорм → <Коллекция: Справочники/Документы/...> → <Имя объекта>`. На каждом уровне: `Использовать`, `Исключения` (шаблоны со `*`, например `"Классификатор*"`), флаги видов тестов (`Новый`, `Существующий`, `Список`, `Выбор`, `Основная`...), `ОбычныеФормы`/`УправляемыеФормы`; на уровне объекта ещё и имя конкретной формы (`"ФормаДокумента": false`).

- **Чёрный список** — отключить коллекции (`"Перечисления": false`), отсеять балласт шаблонами (`"Исключения": ["Классификатор*", "Рег*", "Удалить_*"]`), точечно погасить объекты (`"Заказ": false`).
- **Белый список** — все виды тестов в `false` на уровне `ОткрытиеФорм`, а у нужных объектов включить нужные виды (`"бит_ФормаВводаБюджета": {"Существующий": true, "Список": true}`). Готовый шаблон: `smoke-my.json`.
- Отключение `Использовать` у родителя гасит ветку целиком (включённый ниже объект его не оживит); остальные флаги наследуются с возможностью переопределить снизу.

Полная документация: <https://bia-technologies.github.io/yaxunit/docs/features/smoke/opening-forms/>

Результат: `reports\junit.xml`, `reports\report.json`, `reports\exitcode.txt` (0 — успех, 1 — есть ошибки), лог — `reports\tests.log`.

Приоритет параметров: значения по умолчанию → JSON-файл → ключи командной строки (`RunUnitTests=...;showReport=true`).

## 4. Возможности движка

- fluent-утверждения `ЮТест.ОжидаетЧто(...)` (в т.ч. проверка объектов ИБ);
- конструкторы тестовых данных, «пустышки», фикстуры из макетов, случайные значения;
- **Мокито** — перехват/подмена вызовов методов;
- предикаты, контексты (клиент/сервер), события, зависимости между тестами, дымовые тесты;
- отчёты: jUnit, JSON, allure (см. `reports` в `test-config.json`).
