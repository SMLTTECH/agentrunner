# Смок-тесты: расширение Smoke (открытие форм)

Каталог — исходники расширения **`Smoke`** для движка тестирования [YAxUnit 25.12](../YAxUnit/README.md).
Расширение ставится в тестовую базу вместе с движком `YAXUNIT` и проверяемым расширением `AgentRunner`
(на стенде все три установлены; актуальное состояние базы: `sd-1ctest03\BitFinans_Barabanov_Empty`).

- `src/` — исходники расширения (префикс объектов `ДТ`):
  - `ДТОткрытиеФорм` + служебные — официальный дымовый модуль YAxUnit «ОткрытиеФорм» (без изменений);
    работает **только по метаданным основной конфигурации**, объекты расширений не видит.
  - `ДТОткрытиеФормРасширения` (клиентский) + `ДТОткрытиеФормРасширенияСлужебныйВызовСервера` (серверный) —
    **наш модуль**: открывает все явно созданные формы расширения `AgentRunner`.
- Конфиг запуска — `..\..\YAxUnit\smoke-ar.json`, отчёты — `..\..\YAxUnit\reports\smoke-ar-*`.

## Как работает модуль форм расширения

1. `ДТОткрытиеФормРасширения.ИсполняемыеСценарии()` вызывает серверную функцию
   `ФормыРасширения("AgentRunner")`. Имя расширения — в функции `ИмяРасширения()` клиентского модуля.
2. Серверная функция ищет объекты расширения в общих коллекциях метаданных
   (`Метаданные.Справочники`, `.Обработки`, `.РегистрыСведений`, ... и `.ОбщиеФормы`), отбирая объекты по
   `ОбъектМетаданных.РасширениеКонфигурации().Имя` и праву «Просмотр». Список **динамический** — новые формы
   подхватываются сами, при отсутствии расширения тесты просто не регистрируются (предупреждение в журнале).
3. На каждую форму регистрируется клиентский тест «получить → открыть → обновить → закрыть».
   Форма открывается с параметром **`АвтоТест = Истина`**.

### Две платформенные тонкости, без которых ничего не работает

- **Адресация формы — только дескриптором основной формы.** Из чужого расширения `ПолучитьФорму`
  понимает `Справочник.ar_X.ФормаОбъекта`, `Обработка.ar_X.Форма`, `РегистрСведений.ar_X.ФормаЗаписи`,
  `ОбщаяФорма.ar_X`, но **не** реальное имя формы: `Справочник.ar_X.ФормаЭлемента` даёт
  «Неизвестное имя формы». Поэтому `ДескрипторФормы()` переводит стандартное имя формы в дескриптор
  (`ФормаЭлемента/ФормаДокумента → ФормаОбъекта`, `ФормаОбработки/ФормаОтчета → Форма`, и т.д.).
  Форма с **нестандартным** именем в прогон не попадает — в журнале будет предупреждение «форма ... пропущена».
- **Ветка `АвтоТест` в `ПриСозданииНаСервере`.** Все формы расширения обязаны начинаться с
  ```bsl
  Если Параметры.Свойство("АвтоТест") Тогда
      Возврат;
  КонецЕсли;
  ```
  Без неё смок падает на формах, чья инициализация зависит от данных или состояния
  (пример: `ar_МастерНастройки` закрывается, если мастер уже выполнен).

## Чек-лист: добавить/проверить новую форму (для агента)

1. Форма создаётся в `src/` расширения AgentRunner как обычно. Трогать тесты **не нужно** —
   форма подхватится автоматически, если:
   - имя формы стандартное (`ФормаЭлемента`, `ФормаСписка`, `ФормаВыбора`, `ФормаЗаписи`, `Форма`,
     `ФормаНастроек`, `ФормаВарианта`, ...) — см. `ДескрипторФормы()`;
   - в `ПриСозданииНаСервере` первой строкой стоит ветка `АвтоТест`;
   - форма не требует обязательных параметров открытия.
2. Если нужно проверить формы **другого расширения** — поменяйте возвращаемое значение
   `ИмяРасширения()` в `ДТОткрытиеФормРасширения` (имя — как расширение зарегистрировано в базе,
   у стенда это `AgentRunner`).
3. Прогон (см. также `../YAxUnit/README.md`):
   - загрузить обновлённый Smoke в базу:
     `powershell -File .claude\skills\db-load-xml\scripts\db-load-xml.ps1 -V8Path "C:\Program Files\1cv8\8.3.27.2325\bin" -InfoBaseServer sd-1ctest03 -InfoBaseRef BitFinans_Barabanov_Empty -UserName Администратор -ConfigDir tests\smoke\src -Mode Full -Extension Smoke -UpdateDB`
   - запустить тесты (обязательно с MSYS-префиксом из Git Bash):
     `MSYS2_ARG_CONV_EXCL="*" MSYS_NO_PATHCONV=1 "C:\Program Files\1cv8\8.3.27.2325\bin\1cv8c.exe" ENTERPRISE /S "sd-1ctest03\BitFinans_Barabanov_Empty" /N "Администратор" /C "RunUnitTests=D:\ba\dev\agentrunner\YAxUnit\smoke-ar.json"`
   - результат: `YAxUnit\reports\smoke-ar-exitcode.txt` (0 = зелёный), детали — `smoke-ar-junit.xml`, лог — `smoke-ar-tests.log`.

## Найденные баги (прогон 2026-10-02: 41 тест, 38 OK / 3 ошибки)

Это ошибки **расширения**, не тестов — смок отработал правильно. Тестировщик функциональность не правит,
задачи на исправление — через конвейер.

1. **`ar_ТестТулов.Форма`** (основная ветка, `src/DataProcessors/ar_ТестТулов`).
   `ПриСозданииНаСервере` (без ветки `АвтоТест`) вызывает `ЗаполнитьТаблицуИнструменты` →
   `ПервыйДоступныйДокумент` (`Ext/ObjectModule.bsl`, ~строка 1134): запрос `ВЫБРАТЬ ... Т.Номер` строится
   для **всех** документов конфигурации подряд, а у документов с нулевой длиной номера поля `Номер` нет
   («Поле не найдено Т.Номер») → форма падает при открытии у любого пользователя.
   Рядом лежит `ПервыйЭлементДокумента` (~строка 1199) — там защита через `ДлинаНомера` уже есть,
   в `ПервыйДоступныйДокумент` её не хватает. Плюс форме нужна ветка `АвтоТест`.
2. **`ar_Диалоги.ФормаЭлемента` и `ar_Диалоги.ФормаСписка`** (задача agentrunner-26, worktree `wt/agentrunner-26`;
   её сборка в момент прогона была развёрнута на стенде). В `&НаСервере`-процедуре
   `ОтправитьНаСервере` вызывается клиентский `ПоказатьПредупреждение` (ФормаЭлемента ~строка 122,
   ФормаСписка ~строка 133) → «Процедура не определена (ПоказатьПредупреждение)» уже на
   `ПолучитьФорму`, форма не открывается вообще. Плюс: у обеих форм нет ветки `АвтоТест`.

## Подводные камни (всё, что всплыло)

- **YAxUnit пишет отчёты только по `reportPath` + `reportFormat`.** Ключ `reports` (массив) обработчик
  сохранения игнорирует: без `reportPath` пишутся только `tests.log` и `exitcode`, junit/JSON — нет.
- **Не трогать файлы в `reports\` во время прогона** (читать/удалять/чистить): YAxUnit падает с
  «Ошибка совместного доступа к файлу» и остаётся exitcode=1 без отчётов. Ждать завершения процесса `1cv8c.exe`.
- **Имя тестового метода не должно совпадать с методом глобального контекста**: метод `ОткрытьФорму`
  в общем модуле не компилируется («Процедура ... уже определена») — поэтому тест называется
  `ОткрытьФормуРасширения`.
- **Клиентский вызов в `&НаСервере`-процедуре формы** (`ПоказатьПредупреждение`, `ОткрытьМодальнуюФорму`, ...)
  ломает форму целиком — падение при `ПолучитьФорму`, ещё до каких-либо действий пользователя.
- **Загрузка расширения может повиснуть**: batch-конфигуратор иногда остаётся живым процессом `1cv8.exe`,
  ждущим модальный диалог, и держит блокировку базы. Проверять `tasklist /FI "IMAGENAME eq 1cv8.exe"`,
  висящий процесс снимать; «мёртвые» сессии конфигуратора отпускают блокировку сами через десятки минут.
- **Стенд ≠ локальный `src`.** Стенд живёт своей сборкой (пул разворачивает ветки задач): в прогоне
  2026-10-02 было 41 форма — на стенде есть формы `ar_Диалоги` из задачи agentrunner-26, которых ещё нет
  в локальной ветке. Смок проверяет то, что реально развёрнуто, — это правильно.
- Расширение `Smoke` правится как любые XML-исходники 1С: файлы в UTF-8 **с BOM**, CRLF;
  регистрация модуля — в `src/Configuration.xml` (`ChildObjects`) и `src/ConfigDumpInfo.xml`.
