# Открытие диалогов агента из внешнего кода

Тема 3 [классификатора](../%D0%9A%D0%BB%D0%B0%D1%81%D1%81%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%82%D0%BE%D1%80.md).

## Суть

Как из кода внешней доработки (расширение `bitfin_addition_main`, другая обработка той же базы) открыть
список диалогов агента по заявке НСИ или другому предмету - и не упасть там, где расширение AgentRunner
отключено или не установлено, а у пользователя нет прав на справочник «Диалоги агентов».

## Пример

Блок рассчитан на копирование целиком в модуль управляемой формы потребителя: клиентская процедура
открывает форму, серверная функция предварительно проверяет доступность. Зачем нужна каждая проверка -
в пояснениях ниже.

```bsl
// Открывает список диалогов агента по предмету (заявке НСИ) с проверками доступности.
//
// Параметры:
//  Заявка - ОпределяемыйТип.ar_ПрикладнойОбъект - предмет диалогов, например заявка НСИ.
//
&НаКлиенте
Процедура ОткрытьДиалогиПоЗаявке(Заявка)

	// Поиск объекта метаданных по имени и право чтения проверяются на сервере:
	// клиент сам надёжно определить доступность расширения не может.
	Доступность = ДиалогиАгентаДоступны();
	Если Не Доступность.Доступно Тогда
		ПоказатьПредупреждение(, Доступность.Причина);
		Возврат;
	КонецЕсли;

	Попытка
		ПараметрыФормы = Новый Структура("Предмет", Заявка);
		ОткрытьФорму("Справочник.ar_Диалоги.Форма.ФормаСписка", ПараметрыФормы);
	Исключение
		// Прочие ошибки открытия не проглатываются: пользователь видит причину.
		ПредставлениеОшибки = ОбработкаОшибок.КраткоеПредставлениеОшибки(ИнформацияОбОшибке());
		Текст = СтрШаблон(НСтр("ru = 'Не удалось открыть диалоги агентов: %1';
			|en = 'Failed to open agent dialogs: %1'"), ПредставлениеОшибки);
		ПоказатьПредупреждение(, Текст);
	КонецПопытки;

КонецПроцедуры

// Проверяет, что расширение установлено и включено, а у пользователя есть право на справочник.
//
// Возвращаемое значение:
//  Структура - Доступно - Булево - открывать форму можно;
//              Причина  - Строка  - понятная причина отказа, пустая строка при доступности.
//
&НаСервереБезКонтекста
Функция ДиалогиАгентаДоступны()

	Результат = Новый Структура("Доступно, Причина", Ложь, "");

	// Обращение Метаданные.Справочники.ar_Диалоги при отключённом или не установленном
	// расширении бросает исключение, поэтому объект сначала ищут по имени.
	СправочникДиалогов = Метаданные.Справочники.Найти("ar_Диалоги");
	Если СправочникДиалогов = Неопределено Тогда
		Результат.Причина = НСтр("ru = 'Диалоги агентов недоступны: расширение AgentRunner
			| не установлено или отключено.';
			|en = 'Agent dialogs are unavailable: the AgentRunner extension
			| is not installed or disabled.'");
		Возврат Результат;
	КонецЕсли;

	// Без права чтения форма не откроется или покажет пустой список; проверяем до открытия.
	Если Не ПравоДоступа("Чтение", СправочникДиалогов) Тогда
		Результат.Причина = НСтр("ru = 'Диалоги агентов недоступны: нет права чтения
			| справочника «Диалоги агентов».';
			|en = 'Agent dialogs are unavailable: no read right on the agent dialogs catalog.'");
		Возврат Результат;
	КонецЕсли;

	Результат.Доступно = Истина;
	Возврат Результат;

КонецФункции
```

Вызов для заявки НСИ:

```bsl
ОткрытьДиалогиПоЗаявке(Заявка); // Заявка - ДокументСсылка.бит_мдм_ЗаявкаНаИзменение
```

## Откуда имя формы

Полное имя `Справочник.ar_Диалоги.Форма.ФормаСписка` - то же, которым штатная подключаемая команда
«Диалог с AI» (механизм БСП) открывает список из формы предмета: она передаёт объект параметром
`Предмет`. Короткое имя `Справочник.ar_Диалоги.ФормаСписка` платформа тоже допускает - так список
открывает команда «Мои вопросы»; в примере взято полное имя.

## Параметры формы

Форма списка читает два параметра:

| Параметр | Тип | Что делает |
|---|---|---|
| `Предмет` | ссылка состава `ОпределяемыйТип.ar_ПрикладнойОбъект` | отбор списка по объекту; пустой или незаполненный - отбор не ставится |
| `ТолькоМоиВопросы` | Булево | вопросы текущего пользователя в состоянии «Ожидает ответа» |

В состав типа предмета входят шесть ссылок: `Документ.бит_мдм_ЗаявкаНаИзменение` (заявка НСИ),
`Справочник.Контрагенты`, `Справочник.БанковскиеСчета`, `Справочник.Организации`,
`Справочник.Пользователи`, `Справочник.УчетныеЗаписиЭлектроннойПочты`. Ссылка иного типа - ошибка
открытия: предмет сравнивается в запросе списка. Второй параметр используется самостоятельно:

```bsl
ОткрытьФорму("Справочник.ar_Диалоги.Форма.ФормаСписка", Новый Структура("ТолькоМоиВопросы", Истина));
```

## Как ведёт себя список, открытый с предметом

Показываются все диалоги объекта - отборы очереди (пользователь, состояние) применяются только при
открытии без предмета. Над списком - надпись «Диалоги по объекту: \<предмет\>» и команда
«Начать диалог»; штатная кнопка «Создать» скрыта: диалог начинается с обязательного выбора агента.

## Зачем проверки обязательны

- **Отключённое расширение.** Внешний код живёт в той же базе, но расширение может быть отключено
  или не установлено (обновление, временный сдвиг при слиянии, снятый флажок). Обращение
  `Метаданные.Справочники.ar_Диалоги` к отсутствующему объекту бросает исключение ещё до открытия
  формы. Публичного метода БСП «объект метаданных существует» нет: в `ОбщегоНазначения` похожая
  проверка - приватная процедура, бросающая исключение. Поэтому объект ищут по имени:
  `Метаданные.Справочники.Найти("ar_Диалоги")`.
- **Права.** Право на справочник ограничивает и открытие формы, и данные в ней. Право проверяют
  платформенной функцией `ПравоДоступа("Чтение", …)` до открытия; без права форму не открывают.

## Что увидит пользователь без роли расширения

Серверное ограничение формы: пользователь без роли расширения видит только свои диалоги (инициатор
либо участник) - это параметр запроса списка, который с клиента не снять. То есть открытие по предмету
не покажет чужие диалоги: будут видны только диалоги этого объекта, где пользователь инициатор или участник.
