# Ядро: запуск агента, консоль, встроенные инструменты

Тема 2 [классификатора](../%D0%9A%D0%BB%D0%B0%D1%81%D1%81%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%82%D0%BE%D1%80.md). Расширяет тему [Подключаемые инструменты](podklyuchaemye-instrumenty.md).

## Суть

Ядро превращает задачу в **запуск** — фоновое задание с уникальным `RunId`. Внутри запуска работает **цикл агента**:
модель рассуждает, вызывает инструменты, каждый вызов проходит проверку прав, всё пишется в журнал.
Человек наблюдает и управляет через **консоль агентов**.

| Часть | Модуль | Роль |
|-------|--------|------|
| Источники запуска | `ar_Планировщик`, `ar_Диалог` | cron, рутины, упоминания, подписки; ручной запуск из диалога |
| Запуск | `ar_RuntimeЗапуск` | проверка лимитов, `RunId`, фоновое задание, остановка и возобновление |
| Цикл | `ar_RuntimeЦикл` | шаги «контекст → модель → инструменты», паузы, хуки |
| Права | `ar_ПравилаДвижок` | решение по каждому вызову: выполнить, подтвердить, отказать |
| Журнал | регистры `ar_Запуски`, `ar_СобытияЗапуска`, `ar_ДействияАгента` | одна строка на запуск, события и действия по шагам |
| Подтверждения | `ar_Подтверждение`, `ar_ОчередьApproval` | очередь действий, ожидающих решения оператора |
| Консоль | `ar_КонсольАгентов`, `ar_КонсольДанные` | экран оператора и поставщик его данных |

## Консоль агентов

Общая форма `ar_КонсольАгентов`, пункт подсистемы AgentRunner. Две вкладки — «Запуски» и «Агенты» — с общим периодом.

| Зона | Что показывает |
|------|----------------|
| Быстрый отбор | «Работают», «Требуют внимания», «Все»; плюс период, агент, ответственный, статусы, триггер, «только с ошибками», «только автономные» |
| Сводка | работают · ждут оператора · ожидают подтверждения · ошибок за сутки |
| Список запусков | агент, статус, старт, этап, шаги, длительность, живость, стоимость; не более 200 строк |
| Строка здоровья | состояние регламентных заданий планировщика (давно не запускались, отключены) |
| Команды | открыть запуск (карточка со всеми шагами), остановить, возобновить, очередь подтверждений, созданные объекты, открыть агента и профили |

Правила:

- **Видимость.** Полноправный пользователь видит все запуски. Остальные — только «свои»: где они ответственные по
  профилю запуска, либо пользователь агента, либо инициатор запуска без агента. Фильтр встроен в `ar_КонсольДанные` на
  сервере; форма собственных запросов к регистрам не делает.
- **Обновление.** Список, сводка и здоровье — раз в 60 с (можно отключить); колонка «Живость» пересчитывается на клиенте
  каждые несколько секунд без обращения к серверу.
- **Остановить** доступно для работающего запуска и для трёх пауз; запуск получает статус «Прерван». Остановка не
  мгновенная — текущий шаг может завершиться.
- **Возобновить** доступно только для «Прерван» при наличии снимка состояния. Если запуск был прерван посреди шага,
  уже начатые изменяющие действия могут выполниться повторно — консоль предупреждает об этом.

## Состояния запуска

| Группа | Статусы | Примечание |
|--------|---------|------------|
| Работа | `Создан`, `Выполняется` | пульс (heartbeat) пишется на каждом шаге |
| Ждёт решения | `ПриостановленДляПодтверждения`, `ПриостановленДляВвода`, `ПриостановленДляСобытия` | подтверждение, ответ на `ask_user`, `wait_for_event` |
| Завершён | `Завершён` | итог, токены, стоимость записаны |
| Ошибка или лимит | `ОшибкаВыполнения`, `ДостигнутМаксимумШагов` | в консоли — группа «Ошибка» |
| Прерван | `Прерван` | остановка оператором или зависание; возобновляется со снимка |
| Прочее | `Отменён`, `ОтклонёнГлобально`, `ОшибкаНесовместимоеСостояние` | в консоли — группа «Завершено» |

Зависший запуск (пульс перестал обновляться) находит регламентное задание очистки; для пауз порог свой.

## Цикл агента

Шаг: собрать контекст (промпт, память, навыки, описания инструментов, план) → вызвать модель (повторы и резервный
провайдер) → разобрать ответ. Нет вызовов — запуск завершён. Есть — для **каждого** вызова проверяются права.
Цикл идёт, пока `шагов < МаксШагов` агента; на пути — [хуки](#хуки) и необязательный план работы (`update_plan`).

### Права вызова

Проверки идут последовательно, первая же отказавшая прерывает цепочку:

1. инструмент существует и включён; 2. он в наборе агента; 3. роль 1С; 4. лимиты (`МаксДействий`, `МаксСуммаДействия`);
5. запрещённые объекты (deny-list, для записи и фиксации); 6. матрица режима автономии.

| Режим агента | Чтение | Черновик | Запись | Фиксация |
|--------------|--------|----------|--------|----------|
| Ручной | выполнить | подтверждение | подтверждение | подтверждение |
| АвтоПорог | выполнить | выполнить | подтверждение | подтверждение |
| Автономный | выполнить | выполнить | выполнить | подтверждение |
| ТолькоЧтение | выполнить | отказ | отказ | отказ |

Флаг инструмента `ТребуетПодтверждения` принуждает к подтверждению в любом режиме, кроме «ТолькоЧтение». Исключения:
`remember` (служебная запись в память) и `ask_user` подтверждения не требуют.

Исходы: **выполнить** — результат уходит в контекст; **подтверждение** — аргументы предпроверяются «вхолостую»
(ошибка возвращается модели), затем действие ставится в очередь, запуск встаёт на паузу после шага; **отказ** — причина
возвращается модели как результат, и она может выбрать другое действие. Повторный вызов с тем же ключом идемпотентности
не выполняется дважды.

### Хуки

Обработчики жизненного цикла вызываются в 10 точках: до и после шага, вызова инструмента, вызова модели,
подтверждения, а также при старте и завершении запуска. Сбой хука не валит запуск; обработчик может прервать цикл.

## Встроенные инструменты

Около 30 инструментов в шести категориях (полный список — на [диаграмме](../diagrams/core-tools-catalog.html)).

| Категория | Инструменты | Риск |
|-----------|-------------|------|
| Данные и платформа | `search_metadata`, `list_catalogs`, `list_documents`, `read_object`, `read_document`, `query`, `search_text`, `find_references`, `aggregate`, `get_object_structure`, `get_object_history`, `get_recent_changes`, `get_functional_options`, `get_constants`, `get_current_context` | Чтение |
| Отчёты | `run_report`, `get_print_form` | Чтение |
| Память и настройки | `remember`, `recall_memory`, `get_settings`, `set_setting` | Запись (`remember` — без подтверждения; `set_setting` — с подтверждением), Чтение |
| Коммуникации | `prepare_reconciliation_email`, `prepare_payment_reminder_email`, `get_invoice_reminder_history` | Черновик с подтверждением, Чтение |
| Взаимодействие и план | `ask_user`, `update_plan`, `wait_for_event` | пауза запуска / план / ожидание |
| Поиск и аварийная запись | `find_tools`, `describe_tool`, `save_object` | Чтение; `save_object` — Фиксация, подтверждение обязательно |

`save_object` — крайний случай записи любого объекта без прикладного инструмента; предпочтение всегда у специализированных.
Прикладные инструменты (`buh_*`, `files_*`) в ядро не входят — это [пакеты](podklyuchaemye-instrumenty.md).

### Как инструмент попадает к модели

1. При первом старте ядро регистрирует свои инструменты в справочнике `ar_Инструменты` (повторно — кнопкой «Заполнить реестр tools»
   в настройках); пакеты регистрируются только явным действием администратора.
2. Для каждого инструмента считается **доступность**: нужные объекты метаданных и подсистемы конфигурации.
   Недоступный инструмент модели не предлагается.
3. Набор конкретного агента — явный список плюс вычисляемые правила (`ar_ИнструментыПравилаДоступа`); тот же набор
   используется и для описаний модели, и как «белый список» при проверке прав.
4. Описания (`tool_definitions`) уходят в запрос. Недостающие модель находит через `find_tools` и подгружает через
   `describe_tool`; подгруженные остаются в запросе до конца запуска.

## Регламентные задания

Работают круглосуточно: плановые запуски (cron, рутины), очистка зависших, возобновление после подтверждения и
автовозобновление, опрос подписок и упоминаний, ротация сессий, компакция аудита, автообновление памяти. Их состояние
видно в строке здоровья консоли.
