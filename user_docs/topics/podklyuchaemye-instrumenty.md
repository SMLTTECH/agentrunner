# Подключаемые инструменты (пакеты инструментов)

Тема 1 [классификатора](../%D0%9A%D0%BB%D0%B0%D1%81%D1%81%D0%B8%D1%84%D0%B8%D0%BA%D0%B0%D1%82%D0%BE%D1%80.md). Связанная тема — [Ядро](yadro.md): там описано, как агент вызывает любой инструмент.

## Суть

Агент действует только через **инструменты**: произвольный код модель выполнить не может. Часть инструментов
встроена в ядро ([каталог](yadro.md#встроенные-инструменты)), остальные подключаются **пакетами** — без
пересборки расширения `AgentRunner.cfe`.

**Пакет** — дополнительная обработка БСП (`.epf`) с командой-маркером `ar_ToolPack` и тремя функциями в модуле объекта:

| Функция | Назначение |
|---------|------------|
| `ar_ОписаниеИнструментов()` | манифест: пространство имён, версия, инструменты, настройки |
| `ar_ВыполнитьИнструмент(ИмяTool, АргументыJSON, Контекст)` | исполнение вызова, ответ — JSON-строка |
| `ar_ИсполнитьПодтверждённыйИнструмент(…)` | отложенная запись после подтверждения оператором (нужна, если есть изменяющие инструменты) |

Путь через форк `ar_ИнструментыПереопределяемый` тоже существует, но требует пересборки расширения; пакеты нужны,
когда инструменты привязаны к конфигурации или сервису и должны обновляться отдельно (`buh_*`, `files_*`).

## Как работает

**Регистрация** — форма «Пакеты инструментов», только по действию администратора (при старте системы пакеты не
подхватываются):

1. «Найти пакеты инструментов» — запрос к справочнику БСП по маркеру `ar_ToolPack`; сам поиск `.epf` не загружает.
   Манифест кандидата форма читает и проверяет дополнительно.
2. «Установить» — ядро вызывает `ar_ОписаниеИнструментов`. Для пакета с отключённым безопасным режимом форма просит
   дополнительное подтверждение.
3. Манифест проверяется целиком: любая ошибка — отказ всему пакету, частичной регистрации нет.
4. Запись пакета и инструментов в реестр — одной транзакцией; затем пересчёт доступности, **проба отложенного
   исполнителя** и создание недостающих настроек.

**Проба отложенного исполнителя.** Сразу после регистрации ядро проверяет, реализует ли пакет обязательный для
изменяющих инструментов метод `ar_ИсполнитьПодтверждённыйИнструмент`: метод вызывается с зарезервированным именем
`ar_probe`, на которое пакет обязан ответить отказом без записи в базу. Результат виден в списке пакетов в колонке
**«Отложенное исполнение»** (`Да` / `Нет` / `—` — признак ещё не проверялся, у пакетов, зарегистрированных до
появления пробы). Пакет без исполнителя регистрируется, но его инструменты с `ТребуетПодтверждения = Истина`
остаются недоступными, а в служебном логе появляется `package_without_deferred_executor`. Пакет с таким
инструментом лучше переподтвердить после обновления: проба выполняется заново.

**Вызов**: цикл агента → движок прав → диспетчер → шлюз к пакету → `ar_ВыполнитьИнструмент`. Исключение внутри пакета
превращается в `{"error": …}`, агент продолжает работу. Если по режиму автономии или флагу инструмента нужно
подтверждение, **цикл ставит действие в очередь сам, до вызова пакета**; инструмент, получивший управление,
ставит в очередь только черновики и записи, которые режим разрешил (см. [Ядро](yadro.md#права-вызова)).

**Подтверждение**: изменяющий инструмент не пишет в базу сам — ответ `approval_id` + `queued_for_approval`. После решения
оператора ядро вызывает исполнитель пакета; он пишет в транзакции и возвращает `{Выполнено, DocumentRef, Сообщения}`.

Подтверждение может потребоваться инструменту, который его не объявлял: в ручном режиме автономии ядро отправляет
на подтверждение **любое** действие кроме чтения, в режиме «Авто по порогу» — «Запись» и «Фиксацию». Поэтому
исполнитель нужен пакету, у которого есть инструменты с уровнем риска «Черновик», «Запись» или «Фиксация», а не
только с `ТребуетПодтверждения = Истина`. Если исполнителя нет:

- подтверждение **не ставится**, в очереди подтверждений записи не появляется, инструмент не вызывается — агент
  получает отказ `approval_unsupported_by_package` с текстом «Инструмент … требует подтверждения оператора в режиме
  «…», но пакет … не умеет исполнять подтверждённые действия. Действие не выполнено.»; режим автономии при этом не
  обходится — действие без подтверждения не выполняется;
- если запись очереди была создана раньше (до перерегистрации пакета), одобрение возвращает понятный отказ
  `no_executor_for_action:package_has_no_executor` вместо платформенной ошибки
  «Метод объекта не обнаружен (`ar_ИсполнитьПодтверждённыйИнструмент`)», а в служебный лог пишется
  `package_approved_executor_missing`.

Если решение оператора пришло по записи, чей запуск уже завершён (например, в чат отправили новое сообщение),
оператор видит «Решение сохранено. Запуск уже завершён (…) и продолжен не будет. Действие: выполнено / не
выполнено (…)» — вместо технического `unexpected_status`.

**Контроль изменений**: «Проверить изменения» сверяет хеш манифеста; при расхождении пакет получает статус
«ТребуетПереподтверждения», его инструменты недоступны до «Переподтвердить». «Отключить» выключает инструменты,
история вызовов остаётся.

## Уровни риска

| Уровень | Подтверждение | Смысл |
|---------|---------------|-------|
| `Чтение` | нельзя требовать | только чтение |
| `Черновик` | по решению автора | готовит черновик, ничего не проводит |
| `Запись` | обязательно; исключение — явное `ОбоснованиеЗаписиБезПодтверждения` | изменяет данные |
| `Фиксация` | обязательно, без исключений | необратимое действие |

## Правила автора пакета

- Имя инструмента начинается с пространства имён пакета (`[a-z][a-z0-9_]{1,30}`, уникальное): `demo_echo`, `buh_…`.
- Манифест — схема **2**; пакеты со старыми ключами отклоняются (`legacy_manifest_keys`).
- Без `Выполнить()` и `Вычислить()`; диспетчеризация внутри пакета — условиями.
- Изменяющий инструмент ставит действие в очередь (`ar_Подтверждение.Поставить`), а не пишет сам.
- Обязательный метод `ar_ИсполнитьПодтверждённыйИнструмент` нужен пакету, у которого есть инструменты с уровнем
  риска не «Чтение»: ядро может отправить их на подтверждение по режиму автономии, а исполнить одобренное — только
  этим методом. Для неизвестного имени он отвечает `no_executor_for_action:<имя>` и ничего не записывает — на таком
  ответе основана проба при регистрации (зарезервированное имя `ar_probe`).
- Секреты и ПДн в ответах и журнале маскируются; пользовательские тексты — через `НСтр`.
- Аргументы модели принимаются по правилам раздела [«Аргументы модели»](#аргументы-модели).

## Аргументы модели

Модель переписывает строки по-своему (регистр, пробелы, латиница вместо кириллицы): точное сравнение даёт ложный
отказ, а отказ с неверной причиной — цикл повторов. Правила обязательны для каждого инструмента пакета; ревью
проверяет их по каждому аргументу нового или изменённого инструмента.

1. **Перечислимые значения** — `enum` в схеме аргумента; коды латиницей (строковые ключи контракта — исключение
   правила «без латиницы») и единообразно с соседними полями: не `ok` в одном поле и «ок» кириллицей в другом.
   Сравнение — без регистра и крайних пробелов.
2. **Копируемые идентификаторы** (хеши, GUID, id пунктов) — сравнение `НРег(СокрЛП(..))`; формат проверяется до
   сравнения: искажённый идентификатор — свой код (`invalid_<поле>`), а не ошибка «данные изменились, перечитай».
3. **Объект, который модель выбирает** (файл, документ, элемент справочника, кандидат при неоднозначности), —
   `ref`/УИД в ответе (`candidates: [{presentation, ref}]`) и приём `<поле>_ref`. Поиск: `ref` → точное имя →
   ключ, где выровнены только пробелы (НПП, U+202F, U+2007, U+2009, Таб, повторные); регистр, «ё», кавычки, тире в
   ключе не выравниваются — иначе разные объекты получат один ключ.
4. **Терминальный код** (`next = finish`) — только для состояния, которое не исправить аргументом. Неверный
   аргумент (чужой или опечатанный id) — нетерминальная ошибка с правильным значением в ответе. Идентификаторы,
   которые нельзя передавать в изменяющий инструмент, в ответе помечаются (например, `active_for_agent`).
5. **Текст ошибки называет настоящую причину и допустимые значения** (список `field`, имён, id; сколько цифр
   получено). Текст, на вид совпадающий с отправленным значением, модели не помогает.
6. **Ничего не принято — `error`**, а не «успешный» ответ с отказом внутри: ядро отсекает повтор только неудачного
   вызова. Частично принято — успешный ответ со списком отказов. Пустой результат из-за нераспознанного аргумента
   (неизвестный вид объекта, фильтр) — тоже `error` со списком допустимых значений.
7. **Имена полей и значения фильтров** проверяются по списку, который пакет сам отдал модели в этом запуске, а не по
   наличию реквизита в метаданных: иначе модель запишет поле, которое дозаполнять нельзя.
8. **Цитата из текста** (проверка вхождения, не ключ поиска) — одна нормализация для обеих сторон: все пробельные
   символы (U+00A0, U+202F, U+2007, U+2009, ПС, ВК, Таб), все виды кавычек и дефисов (U+2010, U+2011, тире),
   регистр, «ё».
9. **Цифровые реквизиты** (ИНН, КПП, БИК, счёт) сверяются по цифрам и записываются нормализованными цифрами.
10. **Свободная строка** (номер, представление) разбирается с разделителями НПП, U+202F, «№» и всеми видами
    дефисов; если у запуска есть предмет, а строка не разобралась, берётся предмет. Взаимозаменяемые аргументы
    (например, `inn` и `request`) проверяются на согласованность.
11. **Поиск по имени в метаданных и справочниках** — с отбором по владельцу или набору и без помеченных на удаление;
    найдено несколько — отказ, а не `ПЕРВЫЕ 1`. Запись, созданную в этом запуске, ищут по id из ответа, а не по
    тексту комментария.
- `БезопасныйРежим = Ложь` допустим, но фиксируется в журнале и аудите (`package_registered_unsafe`);
  подписи и контрольные суммы `.epf` ядро не проверяет — за источник отвечает администратор.

## Частые отказы регистрации

| Код | Причина |
|-----|---------|
| `package_contract_violation:ar_ОписаниеИнструментов` | нет функции манифеста или она упала |
| `manifest_not_structure` | манифест — не структура |
| `legacy_manifest_keys` / `unsupported_schema_version:<N>` | схема не 2 — пересобрать пакет |
| `invalid_namespace` / `namespace_collision` | неверное или занятое пространство имён |
| `package_has_no_tools` | нет инструментов |
| `name_not_namespaced:<имя>` | имя без префикса пространства имён |
| `invalid_risk_level:<имя>` / `approval_required_for_risk:<имя>` | неверный риск или сочетание с подтверждением |
| `invalid_package_settings` | некорректные настройки пакета |

Механизм недоступен целиком: `subsystem_missing` (нет подсистемы БСП) или `functional_option_disabled`.
